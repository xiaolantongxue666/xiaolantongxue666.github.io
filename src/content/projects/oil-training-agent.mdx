## 问题：教学实训需要一个"可管、可问、可信"的智能体

油气储运教学实训场景中，学员岗位技能训练需要一个能回答专业规程问题、引导补学、并严格按标准作答的智能体。它不是简单的"套壳问答"：答案必须可溯源（引用核验）、流程必须可编排（工作流引擎）、部署必须可在内网离线环境落地。

## 自研 FSM 工作流引擎：问答链路的骨架

不同于把 LLM 直接暴露给用户，系统用自研有限状态机工作流引擎编排整条问答链路：

状态机让每个环节的边界清晰可测——守卫规则可以独立迭代，不会牵连生成逻辑；新增一个处理环节只需要注册状态和转移规则。

## RAG 全链路：从文档到可溯源答案

搭建覆盖"解析→切分→向量化→检索→重排→核验"的完整管线：

- **文档解析与切分**：PDF / DOCX 解析（表格转 Markdown），按章节条款结构化切分，保留"第 X 条"这类条款引用锚点；
- **向量化与检索**：text-embedding-v3 向量化，Qdrant 检索 top20，重排后取 top5 进入生成环节；
- **引用核验**：以 LLM 结构化输出对答案引用做二次核验，**无来源不输出**，有效抑制模型编造标准编号与虚构规程。

## LLM 工程化：多模型网关与安全守卫

- **多 Provider 模型网关**：通义千问 / 讯飞星火 / Mock 降级三级接入，支持运行时切换——内网环境不可用外网模型时自动降级，保证系统可用性；
- **规则化安全守卫**：拦截 Prompt 注入、危险设备指令、编造标准编号，规则独立于生成逻辑，可审计可迭代；
- **能力画像与自适应补学**：基于 EMA 加权更新学员六维能力画像，驱动"薄弱知识点→补学资源"的闭环，让系统不只是问答，而是教学工具。

## 经验与反思

- **工作流引擎的价值在"边界"，不在"功能"。** 状态机拆开后，每个环节可以独立测试、独立替换，这是 416 个测试能真正挡住回归的前提。
- **"无来源不输出"比"输出更流畅"重要。** 教学场景对错误的容忍度远低于通用问答，宁可让模型说"资料中未找到"，也不能编造标准编号。
- **2 核 2G 是真实约束，不是玩笑。** 离线部署倒逼每个组件做减法：Qdrant 用小内存模式、LLM 走远程 API 而非本地推理、SSE 流式输出降低首字延迟。
